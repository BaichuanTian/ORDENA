# CM-002 Reject malformed checkout lines

Request date: November 25, 2026 (America/New_York).
Source baseline: cm-v0.1.0, eb919f130d54e078a8ec6db1abcbc8acbe658cf6.
Work branch: fix/CM-002-order-line-validation. Integration branch: master.

## Request and impact analysis

An order line that is not a dictionary, or lacks unit_price_cents or quantity,
currently raises incidental TypeError or KeyError instead of the calculator's
defined ValueError. Add an explicit shape check before indexing fields.
Do not change valid-order totals, rounding, price limits or quantity limits.

Affected configuration items: src/pos_demo.py, tests/test_line_validation.py,
docs/CM_Plan.md, README.md, CHANGELOG.md, docs/GITHUB_HANDOFF.md and this record.
No dependency, JSON configuration, menu price or stored-data migration is needed.
Risk: overly restrictive validation could reject valid dictionaries; an accidental
arithmetic change could affect totals. Keep existing arithmetic unchanged and
run all existing tests plus structural-input tests. Scope remains the demo module,
not JSON-file schema validation or the complete POS.
